## 1. Executive & Scientific Purpose

`neuroconsumer` is an R package designed as a **stimulus-first controlled visual experimentation environment** for consumer research and visual communication experiments.

The central premise of `neuroconsumer` is that in visual experiments (such as advertising perception studies), researchers must programmatically create, manipulate, validate, and document visual stimuli such that:
1. Experimental manipulations are declarative and reproducible.
2. Invariant parameters across conditions are strictly verified (the only differences between conditions are the intentional experimental manipulations).
3. Areas of Interest (AOIs) are deterministically bound to semantic visual components and retain stable identifiers across variants.
4. Generated stimuli are accompanied by an immutable manifest detailing parameters, structural hashes, and rendering metadata.

```

                      |   Experimental Factors &    |
                      |   Declarative Manipulations |
```

## 3. Core S3 Object Hierarchy

### 3.1 `nc_component`
The atomic unit of visual content. Represents an element in normalized canvas coordinates `[0, 1]` where `(0, 0)` is top-left and `(1, 1)` is bottom-right.
```r
structure(
  list(
    id = "price_tag",
    type = "price", # "product", "brand", "headline", "text", "price", "cta", "background", "shape"
    x = 0.50,
    y = 0.80,
    width = 0.25,
    height = 0.08,
    z_index = 2L,
    visible = TRUE,
    properties = list(
      text = "£19.99",
      font_family = "sans-serif",
      font_size = 24,
      font_weight = "bold",
      fill = "#1E293B",
      color = "#FFFFFF",
      stroke = NA_character_,
      stroke_width = 0,
      opacity = 1.0,
      border_radius = 4
    )
  ),
  class = "nc_component"
)
```

### 3.2 `nc_stimulus`
An ordered composition of visual components representing a single static layout.
```r
structure(
  list(
    id = "ref_stimulus",
    label = "Reference Layout",
    canvas = list(
      width = 1200L,
      height = 900L,
      unit = "px",
      background_color = "#FFFFFF"
    ),
    components = list(
      bg = <nc_component>,
      prod = <nc_component>,
      ...
    )
  ),
  class = "nc_stimulus"
)
```

### 3.3 `nc_manipulation`
A declarative rule mapping experimental factors and levels to component properties.
```r
structure(
  list(
    factor = "price_position",
    levels = c("upper", "lower"),
    target_component = "price_tag",
    parameter = "y",
    values = list(upper = 0.55, lower = 0.82)
  ),
  class = "nc_manipulation"
)
```

### 3.4 `nc_aoi` & `nc_aoi_set`
Defines Areas of Interest directly inferred from components or declared explicitly.
```r
structure(
  list(
    id = "aoi_price_tag",
    component_id = "price_tag",
    label = "Price Tag AOI",
    shape = "rectangle",
    geometry = list(xmin = 0.375, ymin = 0.76, xmax = 0.625, ymax = 0.84),
    pixel_geometry = list(x = 450, y = 684, width = 300, height = 72),
    margin = c(0, 0, 0, 0)
  ),
  class = "nc_aoi"
)
```

### 3.5 `nc_experiment`
The central root container managing factors, variants, references, validation states, and provenance.
```r
structure(
  list(
    metadata = list(
      title = "Price Position and CTA Contrast Study",
      description = "2x2 factorial study on static digital display ads.",
      created_at = "2026-11-02T16:30:00Z",
      r_version = "R version 4.6.2",
      seed = 42L
    ),
    canvas = list(width = 1200L, height = 900L),
    reference_stimulus = <nc_stimulus>,
    manipulations = list(<nc_manipulation>, ...),
    design = <data.frame with condition_id, factor levels>,
    variants = list(cond_1 = <nc_stimulus>, ...),
    aois = list(cond_1 = <nc_aoi_set>, ...),
    invariants = list(
      components_constant = c("product", "brand", "headline"),
      parameters_constant = list(price = c("font_size", "color"))
    ),
    validation = <nc_validation_result>,
    provenance = <list of generation steps and checksums>
  ),
  class = "nc_experiment"
)
```

## 4. Module Architecture & Scientific Responsibilities

### Module A: Stimulus Engine (`R/stimulus.R`, `R/component.R`)
- Enforces normalized float coordinates `[0, 1]` with translation to concrete pixel dimensions on export.
- Handles deterministic rendering via programmatic SVG XML generation.
- Generates SVG semantic elements with embedded component metadata:
  ```xml
  <g id="nc-comp-price" data-component-type="price" data-z-index="2">
     <rect x="450" y="684" width="300" height="72" fill="#1E293B" rx="4"/>
     <text x="600" y="730" text-anchor="middle" fill="#FFFFFF" font-family="sans-serif" font-size="24" font-weight="bold">£19.99</text>
  </g>
  ```
- Supports PNG conversion through base graphics or `rsvg` when available, preserving exact coordinate correspondence.

### Module B: Manipulation Engine (`R/manipulation.R`)
- Declarative API:
  ```r
  exp <- nc_manipulate(exp, factor = "cta_contrast", component = "cta_btn",
                       parameter = "properties.fill",
                       values = list(low = "#94A3B8", high = "#DC2626"))
  ```
- Evaluates full factorial or fractional combinations via `expand.grid`.
- Deep-clones the reference stimulus for each condition and applies only the parameter modifications declared for that condition.

### Module C: AOI Engine (`R/aoi.R`)
- `nc_aoi_from_components()` automatically derives exact bounding-box coordinates for components.
- Retains persistent, invariant AOI IDs (`aoi_{component_id}`) across all conditions.
- Detects geometry anomalies:
  - Component out of canvas bounds (`x < 0`, `y > 1`, `w <= 0`).
  - Unintended AOI overlap (computes intersection-over-union / pairwise box intersection).
- Exports coordinate matrices compatible with major eye-tracking platforms (Tobii TSV format, Gazepoint format, SMI, and generic normalized CSV).

### Module D: Validation Engine (`R/validation.R`)
Distinguishes between 4 levels of equivalence:
1. **Structural Equivalence:** Identical component hierarchy, types, and counts.
2. **Parameter Equivalence:** Parameter differences match *exactly* and *only* the declared experimental manipulations; all invariant parameters remain identical.
3. **Rendered-Pixel Equivalence:** Invariant visual regions produce identical pixel hashes.
4. **Perceptual Equivalence:** Note: Methodological documentation will explicitly clarify that parameter equivalence **does not imply** perceptual equivalence.

- `nc_validate(experiment)` verifies:
  - All factors have valid levels.
  - No undeclared parameter drift occurred between reference and variants.
  - Component boundaries stay within canvas.
  - Overlap matrix is within declared thresholds.
- Outputs an inspectable `nc_validation_report` with detailed diffs.

### Module E: Experiment Engine (`R/experiment.R`, `R/export.R`)
- High-level orchestration of full experimental workflows.
- `nc_manifest()` generates an immutable JSON/CSV summary capturing:
  - Condition IDs and level combinations.
  - MD5/SHA256 checksums of generated SVGs and PNGs.
  - Runtime environment details (`sessionInfo`).
- `nc_export()` exports stimuli, AOI tables, design matrix, and manifest to disk.
- `nc_plot_design()` provides a base R layout matrix displaying all condition variants side-by-side.

## 5. Technical Validation vs. Scientific Validation

The documentation and API will maintain strict epistemic boundaries:
- **Technical validation** answers: *Did the software render the exact geometries, coordinates, and colors requested without undeclared variance?*
- **Scientific validation** answers: *Does this stimulus induce the psychological or cognitive state intended in human participants?*
- `neuroconsumer` explicitly addresses technical validation, leaving scientific inference to empirical testing.
